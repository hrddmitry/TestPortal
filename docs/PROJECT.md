# TestPortal — паспорт проекта

> Для ИИ-ассистента: прочитай этот файл первым, затем `ROADMAP.md` (что делаем и в каком порядке) и последние записи `LOG.md` (что сделано). Не читай весь репозиторий, пока это не нужно: каждый модуль описан своим `MODULE.md`.

## Что это
Многофункциональный игровой портал для одной организации (возможность клонирования под другую организацию рассматривается позже). Целевые возможности: авторизация, роли и права, группы пользователей, внутренний чат, магазин, оплачиваемые задания (награда во внутренней валюте, наружу не выводится), обучение, уведомления, настройки и редактор оформления интерфейса.

Источник функциональных идей: аудит стороннего портала KINGSTORE (файлы `audit-specifications.md` и `audit-checkpoint.md` лежат в Project Files рабочего пространства Perplexity, папка `b24cowork`, пока не в этом репозитории). Копируем механику и структуры данных по описанию, а не код, тексты и оформление.

## Стек
- Backend: Python 3.15.2, FastAPI, SQLAlchemy 2, Alembic, pydantic-settings, psycopg 3. Менеджер окружения: uv.
- База данных: PostgreSQL 18 (контейнер Docker, `compose.yaml` в корне).
- Frontend: React + Vite 8 + TypeScript, линтер Oxlint, Node.js 26 LTS.
- Платформа разработки: Windows, VS Code, PowerShell, Docker Desktop (WSL 2).
- Планируется публикация на VPS, домен пока не проверен.

## Структура репозитория
```
TestPortal/
  compose.yaml        # PostgreSQL в Docker
  .env                # секреты (НЕ в Git), шаблон: .env.example
  backend/
    pyproject.toml, uv.lock, alembic.ini
    migrations/       # Alembic, единая цепочка миграций
    src/backend/
      main.py         # приложение FastAPI
      core/           # настройки, подключение к БД, базовый класс моделей
      modules/<имя>/  # модули предметных областей
  frontend/           # React + Vite + TypeScript
  docs/               # этот каталог: PROJECT.md, ROADMAP.md, LOG.md
```
Состояние папок `core/` и `modules/` — см. `LOG.md` (перестройка в процессе).

## Архитектурные правила (модульный монолит)
Цель: чтобы ИИ при правке читал минимум файлов и не ломал соседей.
1. Одна область — один модуль (`modules/<имя>/`). Внутри: `models.py`, `schemas.py`, `repository.py`, `service.py`, `router.py`, `public_api.py`, `MODULE.md`. Пустые файлы заранее не создаём.
2. Другие модули импортируют только `public_api.py`, не внутренние файлы.
3. Каждая таблица принадлежит ровно одному модулю. Внешние ключи на чужие таблицы допустимы, `relationship()` между модулями — нет.
4. Реакции между модулями (например, «пользователь добавлен в группу») идут через события или сценарии в `facades/`, а не прямыми вызовами.
5. Направление зависимостей контролирует Import Linter (настройка в `pyproject.toml`).
6. Единые имена ограничений в БД через `naming_convention` (`core/database.py`).
7. Структура БД меняется только через миграции Alembic. Миграцию сначала проверяем, потом применяем.
8. У каждого модуля есть `MODULE.md`: назначение, таблицы, зависимости, публичный интерфейс, правила.

## Правила совместной работы
- Работаем поэтапно, один модуль за раз, без распыления.
- Перед созданием любой сущности, таблицы или файла ассистент описывает, что будет создано, и ждёт правок и одобрения пользователя.
- Инфраструктурные шаги ассистент предлагает сам в нужный момент.
- В конце каждого шага ассистент обновляет `LOG.md` и `ROADMAP.md`, и они коммитятся вместе с кодом.

## Принятые решения по данным
### Пользователи (`users`)
- `id` — большое целое, автонумерация PostgreSQL (identity); пропуски допустимы, повторов нет.
- Удаление мягкое (`deleted_at`), удалённого пользователя можно восстановить; `id` остаётся с ним.
- `email` уникален среди всех строк, включая удалённых, хранится в нижнем регистре; адрес удалённого занят до восстановления.
- Поля: email, имя, фамилия, день рождения, местоположение, дата «в компании с», телефон, «о себе», статус (`active`/`blocked`), `created_at`, `updated_at`, `deleted_at`. Аватар добавим вместе с модулем файлов.
- Убраны из аудита: должность свободным текстом, подпись. Руководитель отдела вычисляется из отдела.
- Пароль и вход — в модуле `auth`, не в `users`.
- Где хранятся отдел, должность и роль пользователя, решаем в модуле `access` (чтобы не было круговой зависимости модулей).

### Доступ (`access`) — решения приняты, реализация впереди
- У пользователя ровно одна должность, один отдел, одна роль.
- Права выдаются роли; личные настройки пользователя могут разрешить или запретить право и имеют приоритет. Право — только «можно/нельзя», без областей действия. Уровней наследования два: роль, затем пользователь.
- Коды прав объявляет каждый модуль у себя.
- Группы: пользователь может состоять в нескольких; подгрупп нет. Состав задаётся вручную: конкретные пользователи, отделы или должности. Если отдел или должность включены в группу, новый сотрудник отдела автоматически попадает в группу. Если человек покидает отдел, он выходит и из группы, кроме случая, когда его добавили в группу лично.
- Назначения от группы (курсы и т. п.) выдаются при входе в группу и при новом назначении группе; после выхода из группы остаются, пока их не удалят вручную.
- Участие в чатах: логику ведёт модуль `chat`; при выходе из группы доступ к чату снимается, если человек не добавлен в него вручную. Детали — когда дойдём до чатов.

### Валюты и кошелёк (`wallet`) — впереди
- Валют может быть несколько, админ добавляет их в настройках; в каждом сервисе, где что-то оплачивается, выбираются разрешённые валюты.
- Транзакции всегда записываются конкретному пользователю.
- Начисления по ролям настраивает админ портала в разделе настроек; где физически хранится правило, решим на этапе кошелька (предложение: в `wallet`).
- Валюта наружу портала не выводится.

### Интерфейс
- Скелет интерфейса (кнопки, компоненты) единый; для визуальной части закладываем редактор оформления (модуль настроек).

## Как запустить локально
1. `docker compose up -d` в корне (нужен запущенный Docker Desktop и заполненный `.env`).
2. Миграции: из `backend` — `uv run alembic upgrade head`.
3. API: из `backend` — `uv run uvicorn --app-dir src backend.main:app --host 127.0.0.1 --port 8000 --reload`.
4. Фронтенд: из `frontend` — `npm run dev` (адрес `http://localhost:5173/`, запросы `/api` проксируются на API).
5. Проверка: `http://127.0.0.1:8000/api/health`, документация API: `/docs`.

## Известные подводные камни
- Использовать `127.0.0.1`, а не `localhost`, для базы и прокси: с `localhost` на этой машине подключение к PostgreSQL занимало около 130 секунд.
- PowerShell искажает вложенные кавычки и обратную косую черту в `docker compose exec ... psql -c`; для `\dt` и подобного открывать интерактивный `psql`.
- Файл `.env` содержит пароль, в Git он не попадает (правило в `.gitignore`).
- Предупреждения Git «LF will be replaced by CRLF» безвредны; единые окончания строк запланированы через `.gitattributes`.
- Пока без установки пакета: скрипты вне Alembic и uvicorn требуют `$env:PYTHONPATH = "src"`.

## Решения по пользователям

- Пользователи создаются администратором.
- Самостоятельная регистрация и ссылки-приглашения на старте не предусмотрены.
- В будущем при необходимости можно добавить приглашения и саморегистрацию, не меняя базовую модель `users`.
